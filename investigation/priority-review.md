# Kache evidence priorities

**Current item classifications and repair decisions: [issue-tracker.md](issue-tracker.md).** This tracker supersedes earlier mixed descriptions of bugs, costs and leads.

Pinned baseline: `4ee0f9e2b9673aa16f29c9c7e39bf8d0152671d9`. This checkpoint ranks observed consequences; it is not a production fix, published report or claim that all listed workloads occur in the user's development environment.

| Priority | Evidence | Consequence and limits |
|---|---|---|
| Correct compiled output | [Rust environment inputs](../../audit-key-native-inputs/investigation/report.md) | Unset versus empty `option_env!` values can produce a hit with the wrong runtime result. A separately proven shadowed include macro can retain another checkout's OUT_DIR. Both reproduced independently. |
| Correct generated output | [Build script declarations](../../audit-cargo-build/investigation/report.md) | Cargo-recognized padded environment declarations are dropped from the run-cache prediction; changing the declared variable restores stale generated output. Real Cargo and direct control executed; reproduced independently. |
| Native dependency correctness | [C/C++ cache inputs](../../audit-cc-cuda-adapters/investigation/report.md) | Creating an optional header or exchanging header contents can return obsolete objects. Opt-in link caching also omits changes to libraries selected with `-l`. Actual Clang artifacts and direct compiler controls executed; reproduced independently. |
| Rust documentation/output contracts | [Rust wrapper](../../audit-rust-wrapper/investigation/report.md) | Rustdoc misses nested module, outer included documentation and environment inputs; explicit metadata destinations and diagnostic protocols also fail their respective restoration contracts. Five behavioral proofs reproduced independently; ordinary Cargo exposure differs by case. |
| Publication rollback integrity | [Store checkpoint](../../qa-store-transactions/investigation/report.md) | A failed replacement can leave filesystem metadata and committed SQL mappings from different generations, expose a cache hit after failure, and remove a peer blob during later removal. Both consequences reproduced independently. Requires generated stranded metadata plus injected SQLite ABORT; natural origin/frequency of that combined state remains unproven. |
| Concurrent prewarming reliability | [CI hydration validation](../../qa-ci-hydration/investigation/report.md) | Sync can skip uncommitted extraction residue and fail with concurrent clients sharing a store and distinct runtimes. Both reproduced independently; no persistent wrong bytes established. Healthy five-run measurements passed. |
| Release performance | [Release experiment](../../release-performance/investigation/report.md) | Synthetic documentation edits cause repeated workspace tree work while all 24 library actions remain hits: main 1.754 s versus stable 0.239 s with 4,000 small files. Exact upstream Biome gate remains untested; timings are workload-specific. |
| Remote concurrency and recovery | [Remote request permits](../../remote-permits/investigation/report.md) | Saturated download capacity can lose a valid small hit under a stricter client deadline; local queue timeouts can then suppress healthy reads after capacity recovers. Both reproduced independently. Uniform default-budget control restored successfully. |
| Async runtime responsiveness | [Post-upload GC](../../../kache-d5-investigation/investigation/report.md) | Synchronous pressure GC can occupy async workers and delay unrelated health responses. One-worker and conditional two-worker main/shard failures; sixteen-worker controls responsive. This does not establish ordinary multi-worktree Cargo slowdown. |
