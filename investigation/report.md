The executed fixture [probe_credentials.py](probe_credentials.py) starts the untouched baseline CLI in an isolated temporary HOME, config, runtime socket and cache. The configured AWS helper starts, sleeps four seconds, then writes a completion marker and valid fixture credentials. A normal `RemoteCheck` receives a one-second deadline. The daemon returns `{"ok":true,"found":false}` in 1.027 seconds, but the helper writes its marker later while that daemon is still alive. The assertion fails with `CREDENTIAL_CHILD_SURVIVED: cancelled remote operation left credential helper running`. [The execution transcript](probe_credentials.execution.txt) preserves the observed tool output; [the raw daemon log](probe_credentials.daemon.log) records the timed-out demand GET and later orderly shutdown.

The cause is `KacheCommandExecute::command_execute` in `src/remote_backend.rs:1053-1084`: it awaits Tokio `Command::output()` without enabling child termination on drop. `RemoteLayout::download_entry_observed` wraps credential acquisition and the GET in `RemoteDeadline::run`, so the timeout drops the future without stopping its child. [Tokio's Command documentation](https://docs.rs/tokio/latest/tokio/process/struct.Command.html#method.kill_on_drop) confirms that default child cancellation behavior. The consequence affects configured AWS profiles whose helpers are slow or hang: owned processes can retain login, network and process resources beyond the request. Repeated-request accumulation is a source inference; it was not measured. Static credentials, compiler-output corruption, process-group cleanup and zombie reaping were not tested.
