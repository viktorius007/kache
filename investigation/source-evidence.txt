15: ## Config file
16: 
17: Open the editor:
18: 
19: ```bash
20: kache config
21: ```
22: 
23: Or edit TOML directly. Kache chooses the first file in this order:
24: 
25: 1. `KACHE_CONFIG`
26: 2. the nearest `.kache.toml`, walking up from the current directory
27: 3. `$XDG_CONFIG_HOME/kache/config.toml` or `~/.config/kache/config.toml`
28: 
29: Kache reads only that one file, plus the [host config](#host-config); a `.kache.toml` does not merge with your user config.
30: 
31: Each process walks up from its own current directory. Cargo compiles packages under the workspace root from the workspace root, but compiles registry and git dependencies, and runs their build scripts, from each package's source directory under `$CARGO_HOME`, so those compiles do not see your project's `.kache.toml`. A daemon that a build starts resolves its file from the directory of the compile that started it, which can be a dependency's source directory. To apply a setting to every compile and to the daemon, put it in your user config or the host config, or point `KACHE_CONFIG` at the file.
32: 
33: If the chosen file is not valid TOML, or a key has the wrong type, Kache ignores the whole file, and the host config with it, and runs on environment variables and defaults without a warning. 34: 
35: The editor covers common fields and keeps the other settings Kache knows. Saving rewrites the whole file: comments and keys Kache does not recognize are dropped, and a file that does not parse is replaced. The editor asks before it first overwrites an existing file.

49: ### Host config
50: 
51: A machine owner can set keys for every build on the machine in `/etc/kache/config.toml`. Kache merges it with the chosen file key by key: a key the chosen file sets wins, and a key it leaves unset comes from the host file. Environment variables still win over both.
52: 
53: The host file reaches CI jobs too. kache-action points `KACHE_CONFIG` at a file of its own that only sets `[cache.remote]`, so a host file like this applies to every job on the runner:
54: 
55: ```toml title="/etc/kache/config.toml"
56: [cache]
57: local_max_size = "200GiB"
58: ```
59: 
60: - `[cache.remote]`, `[cache.planner]` and `[cache.volumes]` are replaced whole. If the chosen file declares one, none of the host file's keys for it apply.
61: - A remote set only through `KACHE_S3_*` variables also replaces the host remote, as long as the chosen file declares no `[cache.remote]`. The same goes for `KACHE_PLANNER_*` and `[cache.planner]`, so a host planner token is never sent to an endpoint the environment picked. A daemon started by a build, `kache daemon start` or `kache daemon restart` does not inherit the variables that select the remote, so it uses the host remote; Kache warns when it starts one that way.
62: - The host file never contributes `[workspace]` declarations. Those belong to a project's `.kache.toml`.
63: - The host file cannot set `ignore_env`. Kache ignores it with a warning, so the host file can never turn environment overrides off. Only the chosen file can; see [Pin file-backed settings](#pin-file-backed-settings).
64: - A host file that cannot be read or parsed is ignored with a warning. `kache doctor` reports it, and lists each host key with whatever overrides it.
65: - `KACHE_HOST_CONFIG` reads another path instead. An empty value turns the host layer off.
66: - `kache config` edits the chosen file, never the host file.
