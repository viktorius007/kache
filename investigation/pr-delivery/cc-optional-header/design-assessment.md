The bounded repair refuses read-set keys when a source or included header spells a header-availability operator, including identifiers continued over CRLF. This retains ordinary read-set reuse while preventing an absent header from silently becoming a new unkeyed input. __has_include_next is included by the conservative prefix match. The guard also scans comments and strings conservatively; a false positive costs caching, not compiler correctness. Arbitrarily synthesized operator tokens are not a complete C preprocessor lexical-analysis claim.

Authoritative preprocessing is already available: preprocess_hash returns the actual expansion hash as well as positive dependency fingerprints. cache_key_under currently chooses the sorted positive-content digest when fingerprints exist and allows read-set memo hits to bypass preprocessing. A future repair could force fresh preprocessing for availability units and retain the expansion hash, preserving object hits at a preprocessor cost. Merely choosing that hash does not establish safe publication, however.

Compile-first discovery receives its read set after compilation. Running an authoritative preprocessor afterward can see a newly created header that the compiled object did not use, then key the old object as if it did. The existing guard covers mutations of positive read inputs and shadowing of names already read; it omits negative header names. Key-first compilation also needs negative existence/search-path checks between preprocessing and compilation. A header created, consumed and deleted in that interval can evade before/after positive read-set validation. Recording exact negative dependencies and resolving compiler/system search paths, macro operands, __has_include_next and transitive relative directories is a larger repair. Compiling the captured expansion instead would also change execute/diagnostic/argument semantics substantially.

The coordinator approved the conservative fallback after this assessment. The PR makes the caching tradeoff explicit. The ordinary direct-mode integration control originally included host stdio.h; on this macOS SDK its availability probes make cache hits intentionally unavailable under the new policy. The control now uses a real compiler and a local macro-built asm alias, preserving its original macro-operand safety and miss/hit/preprocessor-count assertions without binding ordinary cache reuse to host headers. The dedicated availability regression retains real compiler output assertions for cold, unchanged and newly created-header states in both discovery modes; it does not replace the compiler-visible oracle with event counters.
